# Selenium Playwright Migrator — v0.0.5-preview.2

### Fixed

- Cross-process environment identity for `verify-project --run-manifest`: the
  environment fingerprint used for provenance comparison no longer includes the
  loaded-assembly set, so `run` (one CLI process) and `verify-project` (a second
  process on the same host) no longer fail with `EVIDENCE_IDENTITY_MISMATCH`.
  The assembly-set hash is still computed and reported as metadata. This was the
  root cause of the chronically red "Enforce standard migration performance
  budget" step in Full Validation.
- `scripts/install-standalone.ps1`: standalone installer downloads are now robust —
  TLS 1.2 is pinned for Windows PowerShell 5.1, downloads use `-UseBasicParsing`
  with a timeout, and the archive/checksums download retries up to 4 times with
  backoff, honours `HTTPS_PROXY`/`HTTP_PROXY` or an explicit `-ProxyUrl`, and fails
  with an actionable message. Fixes transient "Unable to connect to the remote
  server" when downloading a GitHub Release archive. `scripts/install-standalone.sh`
  gained the matching `curl --retry` / `wget --tries` retries and an empty-file guard.
- `scripts/run-standard-migration-smoke.ps1`: the standard-migration smoke now builds
  a real autonomy workspace before running the final gate — the run output lives
  under `runs/run-001` and `state/autonomy-state.json` plus
  `evidence/autonomy-ledger/anchor.json` are produced by `update-autonomy-state.ps1`
  rather than being absent on a bare CLI run. The final gate is invoked with
  `pwsh` (required by the gate's APIs) instead of Windows PowerShell, so the smoke
  works on Linux CI.
- `scripts/baseline/measure-baseline.ps1`: fixed a PowerShell parse error
  (`$LASTEXITCODE:` read as an invalid variable-with-drive reference) that broke the
  "Validate repository scripts" CI job.
- `AutonomyStateRecoveryTests.Mig06_NewInvocationPreservesCumulativeCycleProof` now
  includes the action's combined output in its failure message so future CI flakes
  are immediately diagnosable.

### Notes

- The scheduled Full Validation workflow had been red for several days (10-01
  through 10-06) on three independent pre-existing defects — the environment
  identity mismatch above, the smoke's Windows-only final-gate invocation, and the
  measure-baseline parse error. All three are fixed in this release. Full Validation
  is expected to go green with this release.
